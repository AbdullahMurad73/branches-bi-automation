# أتمتة وتحليل بيانات الفروع — Power BI

تحويل التقرير الشهري لأحد عشر فرعاً من **عمل يدوي بالنسخ واللصق**
إلى **خط بيانات آلي** يُحدَّث بضغطة زر، مع تحقق تلقائي من سلامة الأرقام.

> ⚠️ **جميع البيانات في هذا المستودع تجريبية ومولّدة عشوائياً.**
> لا يحتوي المستودع على أي بيانات حقيقية لأي جهة. الغرض منه عرض
> **المنهجية والكود** فقط.

---

## المشكلة

أحد عشر فرعاً يرسل كل منهم ملف مبيعات منفصلاً شهرياً — بترويسات متفاوتة،
وصفوف فارغة، ومسافات زائدة تجعل الفرع الواحد يظهر مرتين، وإجماليات
لا تطابق حاصل (الكمية × السعر).

## الحل

| المرحلة | ما يحدث |
|---|---|
| **الاستيعاب** | قراءة **المجلد** لا الملف — أي ملف جديد يدخل التقرير تلقائياً |
| **التنظيف** | توحيد الترويسات والأنواع، إزالة الفراغات، تشذيب النصوص |
| **التحقق** | مقارنة الإجمالي المُرسل بـ (الكمية × السعر) ووسم التعارضات |
| **النمذجة** | جدول تقويم مستقل يُفعّل دوال الذكاء الزمني |
| **العرض** | لوحة تفاعلية: ترتيب الفروع، النمو الشهري، مؤشر سلامة البيانات |

## هيكل المستودع

```
power-query/
  01-combine-branches.m   # دمج وتنظيف ملفات الفروع
  02-date-table.m         # بناء جدول التقويم
dax/
  measures.dax            # 16 مقياساً: أساسية، زمنية، تحليل فروع، جودة
sample-data/
  branch_01..11.csv       # بيانات تجريبية (11 فرعاً × 28 يوماً)
docs/
  methodology.md          # شرح المنهجية بالتفصيل
```

## التشغيل

1. افتح **Power BI Desktop** → `Get Data` → `Blank Query`.
2. افتح `Advanced Editor` والصق محتوى `power-query/01-combine-branches.m`.
3. عرّف المعامل `FolderPath` وأشره إلى مجلد `sample-data`.
4. كرّر الخطوة لـ `02-date-table.m` لإنشاء جدول التقويم.
5. اربط `التقويم[التاريخ]` بـ `المبيعات[التاريخ]` — علاقة واحد إلى متعدد.
6. أضف المقاييس من `dax/measures.dax`.

## أبرز ما في الكود

**التحقق التلقائي** — العمود الذي يكشف الأخطاء قبل أن تصل للوحة:

```m
Table.AddColumn(
    مشذّب,
    "تحقق_الإجمالي",
    each if Number.Abs([الإجمالي] - ([الكمية] * [سعر الوحدة])) < 0.05
         then "سليم"
         else "يحتاج مراجعة"
)
```

**قراءة المجلد لا الملف** — إضافة فرع جديد لا تتطلب تعديل الاستعلام:

```m
المصدر = Folder.Files(FolderPath)
```
